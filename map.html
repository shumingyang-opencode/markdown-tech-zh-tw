Markdown 做的事可以一句話講完：用純文字的語法，寫出結構化的文件。 關鍵在於——語法極少、寫法固定，而「看到什麼就渲染成什麼」的規則一致，學習成本極低。 下面從「核心語法」到「生態系」拆解。

1. 核心語法 · Core Syntax

最常用的十種語法，佔日常寫作 90% 的需求（單元 2–5）。

標題# 到 ######，六級 強調**粗體** *斜體* 清單有序 / 無序 / 巢狀 連結[文字](網址)
圖片![alt](url) 程式碼行內 / 區塊 / 高亮 引用> 引言區塊 分隔線--- 水平線

2. 進階擴展 · GitHub Flavored Markdown

GitHub 在標準 Markdown 上擴充的實用語法（單元 6）。

任務清單- [ ] / - [x] 刪除線~~刪除~~ 表格| 欄位 | 對齊 | 自動連結URL / #issue / @mention
註腳[^1] 底註 Emoji:tada: 表情 HTML 內嵌<details> 等

3. 生態系 · Ecosystem

Markdown 被哪裡使用？掌握語法後，這些都是你的主場（單元 7）。

GitHubREADME · Issue · PR 靜態網站Hugo · Astro · mkdocs 筆記軟體Obsidian · Logseq 文件系統Wiki · 部落格

4. 工具與轉換 · Tools

寫得順手、轉得出去的輔助工具（單元 8）。

編輯器VS Code · Typora · 即時預覽 轉檔pandoc · markitdown 圖表Mermaid 流程圖 檢查markdownlint

箭頭方向即學習順序：先核心語法，再 GFM，最後進入生態系與工具。

小結：Markdown = 「極少的語法」×「一致的渲染規則」。學會核心語法就能寫出 90% 的文件， 補上 GFM 就能在 GitHub 協作，進入生態系就能把 Markdown 變成網站、筆記與文件。
