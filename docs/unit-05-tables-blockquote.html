5.1 表格 · Tables

表格用 | 分隔欄位，第二行用 --- 標示表頭，並可設定對齊：

原始碼 · SOURCE
| 名稱 | 預設 | 說明 |
|:-----|:----:|-----:|
| host | localhost | 主機 |
| port | 8080 | 連接埠（置中） |
| log  | auto | 日誌（靠右） |
渲染結果 · RENDERED
名稱預設說明
hostlocalhost主機
port8080連接埠（置中）
logauto日誌（靠右）

對齊語法：:--- 靠左、:---: 置中、---: 靠右。

表格內的特殊字元：管道符 | 需寫成 \|；程式碼用 ` 包住；換行可用 <br>。表格是 GFM 語法（標準 Markdown 不支援）。

5.2 引用區塊 · Blockquotes

用 > 開頭；巢狀引用用多個 >>；區塊內可放清單、段落與程式碼：

原始碼 · SOURCE
> 這是引用。
>
> - 引用內清單
>
> > 巢狀引用
>
> ```js
> const x = 1;
> ```
渲染結果 · RENDERED
這是引用。
  • 引用內清單
巢狀引用
const x = 1;
引用內換行：每一行都要以 > 開頭；空行也要 >（否則引用結束）。

5.3 分隔線 · Horizontal Rule

三個以上的 ---、*** 或 ___（中間可留空格）：

原始碼 · SOURCE
上面一段

---

下面一段
渲染結果 · RENDERED

上面一段

下面一段

避免誤判：--- 若緊跟在文字下一行（無空行），會被當成「二級標題」而非分隔線。要當分隔線時，前面務必留空行。

5.4 內嵌 HTML

需要進階排版（顏色、摺疊、影片、表格欄合併）時，直接寫 HTML——GFM 允許：

原始碼 · SOURCE
<details>
  <summary>點我展開</summary>
  摺疊內容
</details>

<p style="color: var(--fuchsia)">彩色文字</p>
渲染結果 · RENDERED
點我展開摺疊內容

彩色文字

安全注意：GitHub 會過濾危險 HTML（script、onload 等）。可用的多為展示性標籤（details、table、img、a）。

進階真實情境 Worked Example

情境：撰寫 API 文件——表格 + 引用 + details 摺疊的組合應用

你要為一個 REST API 撰寫端點文件，包含：參數表格、錯誤碼引用、敏感資訊用 <details> 摺疊：

原始碼 · SOURCE
## POST /api/v1/orders

建立一筆新訂單。

### 請求參數

| 參數 | 類型 | 必填 | 說明 |
|:-----|:-----|:----:|:-----|
| product_id | string | ✅ | 商品 ID |
| quantity | integer | ✅ | 數量（≥ 1） |
| note | string | — | 備註（最多 200 字） |

### 錯誤碼

| 代碼 | 意義 | 處理方式 |
|:-----|:-----|:---------|
| 400 | 參數格式錯誤 | 檢查 JSON body |
| 409 | 庫存不足 | 降低數量或稍後重試 |
| 429 | 速率限制 | 等待 `Retry-After` 秒數 |

> ⚠️ 所有請求需帶 `Authorization: Bearer ` 標頭。未帶者一律回 401。

---

深入原理擴充

表格解析中的管道符（Pipe）處理

GFM 表格解析器的工作方式：

  1. 表頭行：以 | 分隔，兩側可有可無 |。解析器計算 | 數量決定欄數。
  2. 分隔行：必須至少三個 ---（或 :-- 等），: 決定對齊。
  3. 資料行：欄數必須與表頭一致。多出來的 | 會被忽略，少的會補空欄。
容易忽略的邊界案例：如果表格欄位內容本身包含 |（例如 SQL 的 UNION | SELECT），必須寫成 \| 轉義。但 GFM 的轉義僅在表格內有效——在普通段落中，\| 會顯示反斜線。另外，表格不能有空行（空行會終止表格，後面的行變成段落文字）。

診斷式疑難排解表

症狀可能原因解決方案
表格整段顯示為純文字分隔行（---）欄數與表頭不一致確保分隔行的 | 數量與表頭行完全一致
引用區塊突然斷掉中間某行忘了加 >引用內每一行（包括空行）都要以 > 開頭
巢狀引用渲染成平行>> 中間有空格或格式不對確保 >> 緊貼，不加空格
分隔線變成了標題--- 前面沒有空行（被當成 setext 標題）在 --- 前加一個空行
<details> 摺疊內容消失details/summary 標籤沒有正確閉合確認 </details> 存在且在內容之後

進階挑戰題

挑戰 1：用 Markdown 撰寫一份「資料庫 Schema 文件」，包含：每個資料表用一個表格列出欄位（名稱/類型/約束/說明）、表與表之間的關聯用引用區塊說明、敏感欄位（密碼 hash 等）用 <details> 摺疊。至少 3 個資料表。
挑戰 2：建立一份「CLI 工具手冊」，每個子命令用一個 H3 標題，下方放參數表格（至少 4 欄）和用法範例（程式碼區塊），常見陷阱用引用區塊標記。最後用 <details> 摺疊進階選項。
挑戰 3：寫一份 Markdown，裡面有一個表格的某欄位包含管道符（需要用 \| 轉義），然後在同一份文件中有一個普通段落也包含管道符——觀察兩處的渲染差異，並寫出解釋。
