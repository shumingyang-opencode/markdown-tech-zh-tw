7.1 GitHub：README / Issue / PR

GitHub 是 Markdown 使用率最高的場合：README 是 repo 的首頁文件、Issue 是問題追蹤、PR 是變更討論。三者都用 GFM。

  • README：首頁名片——專案做什麼、怎麼裝、怎麼用。
  • Issue：問題回報與功能請求（搭配 template 自動化結構）。
  • PR：變更說明、測試結果、關聯 issue（closes #12 自動關閉）。

7.2 靜態網站 · Static Sites

靜態網站生成器（SSG）以 Markdown 為文章來源，配合 frontmatter（YAML 標頭）產出整站：

frontmatter · HUGO
---
title: "我的文章"
date: 2026-08-16
tags: ["markdown"]
---

這是**正文**。
渲染結果 · RENDERED

我的文章

日期：2026-08-16 ｜ 標籤：markdown
這是正文。

工具特色
Hugo極快、單一執行檔
Astro元件化、可帶框架
mkdocs文件站（Material 主題）
VitePressVue 生態、API 文件

7.3 筆記軟體 · Obsidian / Notion

Obsidian 以 Markdown 為儲存格式，支援雙向連結 [[筆記名]] 與 Graph View——你的筆記就是一堆可版本控制的 .md 檔；Notion 底層也是區塊式 Markdown。

7.4 Mermaid：在 Markdown 內畫圖

Mermaid 讓你在程式碼區塊（```mermaid）內用文字畫流程圖/序列圖/甘特圖，GitHub、GitLab、Obsidian 都支援：

原始碼 · SOURCE
```mermaid
flowchart LR
  A[開始] --> B{成功?}
  B -- 是 --> C[部署]
  B -- 否 --> D[回滾]
```
渲染結果 · RENDERED

A[開始] → B{成功?}
B --是--> C[部署]
B --否--> D[回滾]

（支援 Mermaid 的環境會渲染成圖形）

序列圖 · SEQUENCE
```mermaid
sequenceDiagram
  使用者->>伺服器: 登入
  伺服器-->>使用者: token
```
渲染結果 · RENDERED

使用者 → 伺服器: 登入
伺服器 → 使用者: token

7.5 Docs-as-Code 工作流

工作流 · WORKFLOW
1. Markdown 原始檔進 repo（docs/）
2. CI 執行 markdownlint + 建置
3. 發佈到靜態網站（GitHub Pages）
4. 文件與程式碼同 PR 審查

成果：文件可追溯、可自動化、永不過時。
渲染結果 · RENDERED

  2. CI 執行 markdownlint + 建置

7.6 AI 工具與 Markdown

現代 AI 工具（ChatGPT、Copilot、OpenCode）大量以 Markdown 作為輸入/輸出格式：

  • 輸入：把 repo 的 README/文件餵給 LLM 建立上下文。
  • 輸出：LLM 回傳結構化回答（標題、清單、程式碼區塊）。
  • AGENTS.md / CLAUDE.md：以 Markdown 寫的代理指令檔，已是工程主流。
意義：會寫 Markdown = 會跟 AI 工具「精準溝通」。這是新一代軟體工程師的基本功。
