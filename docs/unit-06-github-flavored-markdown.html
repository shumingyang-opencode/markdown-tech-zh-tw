6.1 什麼是 GFM

GitHub Flavored Markdown（GFM） 是 GitHub 在標準 Markdown 上擴充的方言，也是「在 GitHub 協作」的實際標準。它涵蓋：任務清單、刪除線、自動連結、表格（規範化）、註腳、emoji、內嵌 HTML、忽略 Markdown。

為什麼重要：你在 GitHub 寫的 README、Issue、PR、Wiki 全部用 GFM。學會它等於學會「在 GitHub 溝通」。

6.2 任務清單 · Task List

原始碼 · SOURCE
- [x] 完成安裝
- [ ] 撰寫 README
- [ ] 發佈 v1.0
渲染結果 · RENDERED
完成安裝
撰寫 README
發佈 v1.0
注意：任務清單必須是清單的子項，[ ]（未勾）與 [x]（已勾）中間要空格。可巢狀（子任務）且可在 Issue/PR 中被 GitHub 自動統計。

6.3 刪除線 · Strikethrough

原始碼 · SOURCE
~~舊方案~~ 已改為新方案
渲染結果 · RENDERED
舊方案 已改為新方案

6.4 自動連結 · Autolink

GFM 自動把 URL、#issue、@mention、commit SHA 轉成可點連結：

原始碼 · SOURCE
網址 https://github.com 自動變連結。
修復了 #123 的問題。
感謝 @team 的協助。
渲染結果 · RENDERED

網址 https://github.com 自動變連結。
修復了 #123 的問題。
感謝 @team 的協助。

6.5 註腳與 emoji

原始碼 · SOURCE
這是有註腳[^1]的句子。

[^1]: 註腳內容說明。

發佈成功 :tada: :rocket:
渲染結果 · RENDERED

這是有註腳1的句子。
發佈成功 🎉 🚀

Emoji 短碼：:tada: :rocket: :bug: :warning: 等。支援不全的渲染器會原樣顯示短碼。

6.6 忽略 Markdown 語法（跳脫）

想在文件裡「顯示」Markdown 符號而非「觸發」它，用反斜線 \ 跳脫：

原始碼 · SOURCE
\*這不是斜體\*
\# 這不是標題
用 \` 顯示反引號
渲染結果 · RENDERED

*這不是斜體*
# 這不是標題
用 ` 顯示反引號

6.7 Worked Example：Issue 模板

原始碼 · SOURCE
## 問題描述
- [ ] 已搜尋現有 issue

**重現步驟**
1. 開啟設定
2. 點擊「儲存」

**期望**：儲存成功
**實際**：`Error 500`

版本 :bug: v1.2.0
參考 : #45 #88
渲染結果 · RENDERED

問題描述

已搜尋現有 issue

重現步驟

  1. 開啟設定
  2. 點擊「儲存」

期望：儲存成功
實際：Error 500

版本 🐛 v1.2.0
參考 : #45 #88

練習：寫一份「功能請求」Issue 模板——含標題、目標、方案、驗收清單（任務清單）。

看完這單元你應該能說出：
  • 寫出任務清單、刪除線、自動連結、註腳與 emoji。
  • 解釋 GFM 在 GitHub 場景的實際用途（README/Issue/PR）。
  • 使用 HTML 內嵌與忽略 Markdown 語法（\ 跳脫）。
  • 理解 GFM 表格與標準 Markdown 表格的差異。
