8.1 完整 README 實作

一份好的 README 有固定骨架。以下是一次完整的實作，逐段拆解：

README.md · SOURCE
# my-tool

[![build](https://img.shields.io/badge/build-passing-brightgreen)](https://ci.example.com)

用一句話說明這個工具**做什麼、解決什麼問題**。

## 功能
- 快速、輕量
- 支援 CLI 與 API

## 安裝
```bash
npm install -g my-tool
```

## 使用
```bash
my-tool run --config config.yaml
```

## 文件
- [快速開始](docs/quickstart.md)
- [API 參考](docs/api.md)

## 授權
MIT License
拆解 · ANATOMY

① 名稱：H1
② 徽章：巢狀連結 + 圖片
③ 一句話：說明價值
④ 功能：無序清單
⑤ 安裝/使用：程式碼區塊
⑥ 文件：相對路徑連結
⑦ 授權：簡潔收尾

8.2 常見錯誤清單

錯誤原因修正
按 Enter 沒換行段落需空行加空行，或行尾兩空格
巢狀清單跑掉縮排不足/不統一統一用 2 或 4 空格
程式碼區塊沒高亮沒指定語言```python 等
表格歪掉欄數不一致每行 | 數相同
相對路徑圖壞掉以 repo 根為基準docs/img/x.png
區塊被當標題--- 前沒空行分隔線前留空行
中文標點黏字底線強調改用星號強調

8.3 工具鏈

工具用途
VS Code編輯 + 即時預覽 + 擴充（Markdown All in One）
Typora / Obsidian所見即所得編輯
markdownlint語法/風格檢查（CLI 或編輯器擴充）
pandoc轉 PDF/DOCX/HTML
markitdown把 Office/PDF 轉回 Markdown
Mermaid畫圖（流程/序列/甘特）

8.4 風格指南建議

  • 一個 H1：文件只有一個主標題，其餘用 H2+。
  • 星號強調：**/*，不用底線。
  • 圍欄式程式碼：一律指定語言。
  • 清單符號一致：全站統一 -。
  • 表格欄數一致：可讀性優先。
  • 換行用空行：少用行尾雙空格。

8.5 Worked Example：交付前檢查清單

檢查清單 · CHECKLIST
- [ ] 標題結構完整（H1 只有一個）
- [ ] 粗體/斜體語法正確（星號）
- [ ] 所有連結可點（相對路徑正確）
- [ ] 程式碼區塊指定語言
- [ ] 表格欄數一致
- [ ] 跑過 markdownlint 無 error
- [ ] 在 GitHub 上開預覽確認渲染
驗收 · ACCEPT

✅ 全部勾選 → 可以發佈
❌ 任一未勾 → 修正後再交付

最後一步：把 README 貼上 GitHub 開預覽確認渲染——很多錯誤只有「真的渲染」才看得出來。
看完這單元你應該能說出：
  • 從零寫出一份結構完整的 README（含徽章/安裝/使用/授權）。
  • 避開常見錯誤（換行、縮排、反引號數目、表格欄數）。
  • 用 markdownlint 與工具鏈檢查文件品質。
  • 建立個人化的「交付前檢查清單」。
