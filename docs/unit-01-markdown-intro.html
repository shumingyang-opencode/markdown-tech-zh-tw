一句話定義

Markdown 是一種「以純文字撰寫、渲染成結構化文件」的輕量標記語言（lightweight markup language）。 你用一般打字的方式輸入符號與文字，再用任何一款 Markdown 編輯器或渲染器，就能把同一份文字變成帶有 標題、清單、表格、程式碼區塊的美觀文件。

輸入：純文字 · PLAIN TEXT
# 這是標題
**這是粗體**，*這是斜體*。
輸出：結構化文件 · STRUCTURED

這是標題

這是粗體，這是斜體。

重點：Markdown 的原始檔就是人可直接閱讀的純文字—— 就算沒有渲染器，打開原始檔也能看懂內容。這是它與 Word 這類「所見即所得」文件最大的不同。

Markdown 的誕生

2004 年，John Gruber 與 Aaron Swartz 提出 Markdown， 靈感來自當時程式設計師在電子郵件裡用符號排版（例如用 *星號* 表示粗體）的習慣。 目標很明確：

  • 可讀性優先（readability）——原始檔本身就清楚易懂。
  • 易於書寫（ease of writing）——語法少、符號直覺。
  • 只需一套規則就能轉成 HTML，成為當時部落格寫作的好工具。

原文定義：「Markdown is intended to be as easy-to-read and easy-to-write as is feasible.」

Markdown vs HTML vs Word

三者的定位不同，用一張表比較：

比較MarkdownHTMLWord（.docx）
本質 輕量標記語言 全功能標記語言 二進位文件格式
學習成本 低（10 種語法） 中高（標籤多） 中（需滑鼠操作）
原始檔可讀性 極高 低（被標籤淹沒） 不可讀（二進位）
版本控管（Git） 理想（純文字 diff） 可行 困難（binary diff）
典型用途 文件、README、筆記 網頁 正式報告、排版稿
常見誤解：Markdown 不會取代 HTML——它是 HTML 的「更友善的寫法」。 需要精細排版時，Markdown 甚至可以內嵌 HTML 兜底（單元 5 會講）。

誰在用 Markdown

你不必刻意「找地方用」，現代開發者日常已經離不開它：

為什麼值得學

  • 語法極少：常用語法不到十種，一兩天就能上手。
  • 純文字永不過時：不依賴特定軟體版本或格式相容性。
  • 完美配合 Git：每行改動都能被追蹤，團隊協作友善。
  • 一次寫、到處渲染：同一份原始檔可變成網頁、PDF、簡報。
  • 工程師通用語言：在 GitHub、Stack Overflow、技術部落格都講這種語言。

現在就開始練

不需要安裝任何東西，三種方式任選：

  1. 線上試玩：Dillinger 或 StackEdit，左邊寫右邊即時預覽。
  2. 本機 VS Code：安裝「Markdown Preview Enhanced」外掛，寫 .md 檔即可預覽。
  3. GitHub：開個 repo 寫 README.md，GitHub 會自動渲染。
看完這頁你應該能說出：
  • Markdown 是什麼、它與 HTML / Word 的差別。
  • 至少三個使用 Markdown 的日常場景。
  • 它的原始檔為什麼特別適合用 Git 版本控管。
  • 在哪裡可以立刻開始練習寫 Markdown。
