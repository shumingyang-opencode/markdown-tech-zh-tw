4.1 行內程式碼 · Inline Code

用反引號 ` 包住一段文字，變成行內程式碼——適合提及變數、指令、檔名：

原始碼 · SOURCE
執行 npm install 安裝依賴。

變數 score 是數字，設定檔在 config.yaml。
渲染結果 · RENDERED

執行 npm install 安裝依賴。
變數 score 是數字，設定檔在 config.yaml。

行內 code 的陷阱：行內 code 內的反引號需用雙反引號包住（`` `字面反引號` ``）；特殊字元（如 <）不會自動轉義，必要時手動寫實體。

4.2 程式碼區塊 · Code Blocks（圍欄式）

用三個反引號開頭與結尾，第二行指定語言可啟動語法高亮：

原始碼 · SOURCE
```python
def greet(name):
    return f"Hello, {name}!"
```
渲染結果 · RENDERED
def greet(name):
    return f"Hello, {name}!"
語言標記範例語言
常見python、javascript、typescript、go、rust
資料json、yaml、xml、sql
作業bash、sh、powershell、dockerfile
網頁html、css、markdown
GFM 進階：在區塊後可加「註解行」高亮（```python hl_lines="1 3"，部分平台支援）。

4.3 圍欄區塊內顯示反引號

程式碼本身包含三個反引號（如寫 Markdown 教學）時，用更多個反引號當圍欄：

原始碼 · SOURCE
````
```
這是內部的程式碼區塊
```
````
渲染結果 · RENDERED
```
這是內部的程式碼區塊
```

4.4 縮排式程式碼區塊（傳統寫法）

每行縮排四個空格或一個 tab，也是一種區塊寫法（GFM 仍支援，但不建議新文件使用，因無法指定語言高亮）：

原始碼 · SOURCE
    echo "這是縮排式區塊"
    exit 0
渲染結果 · RENDERED
echo "這是縮排式區塊"
exit 0
選擇：新文件一律用圍欄式（```）——可指定語言、可巢狀、不會被誤判。縮排式僅在極舊文件可見。

4.5 HTML 特殊字元安全顯示

在程式碼區塊內，<、>、& 不會被當成 HTML——直接原樣顯示（區塊是「免轉義」區域）：

原始碼 · SOURCE
```html

A & B < 10

```
渲染結果 · RENDERED
<div class="card">A &amp; B &lt; 10</div>

進階真實情境 Worked Example

情境：在 Markdown 文件中嵌入多種語言的執行結果，並用 pandoc 轉 HTML

假設你正在寫一份技術報告，需要展示 Python 處理資料 + bash 管道 + SQL 查詢的完整流程：

原始碼 · SOURCE
## 資料處理流程

**Step 1：Python 清理資料**

```python
import pandas as pd
df = pd.read_csv("raw_data.csv")
df = df.dropna(subset=["revenue"])
df.to_csv("clean.csv", index=False)
print(f"保留 {len(df)} 筆有效記錄")
```

輸出：
```
保留 1,247 筆有效記錄
```

**Step 2：Bash 合併並排序**

```bash
# 合併三個分區的資料
cat clean_*.csv | sort -t',' -k4 -rn > merged.csv
echo "合併完成：$(wc -l < merged.csv) 筆"
```

**Step 3：SQL 查詢前 10 大客戶**

```sql
SELECT customer, SUM(revenue) AS total
FROM merged
GROUP BY customer
ORDER BY total DESC
LIMIT 10;
```

> ⚠️ 確保 Step 1 的 clean.csv 存在再執行 Step 2。
渲染結果 · RENDERED

import pandas as pd
df = pd.read_csv("raw_data.csv")
df = df.dropna(subset=["revenue"])
df.to_csv("clean.csv", index=False)

為什麼選這條路徑：每個步驟用對應語言的程式碼區塊（指定 python、bash、sql），渲染器會分別套用正確的語法高亮。比全部塞在同一個 ```text 裡可讀性好 10 倍——讀者一眼就知道哪段是 Python、哪段是 SQL。

轉 HTML 注意：用 pandoc --highlight-style=tango 轉出的 HTML 會帶有語法高亮的 CSS class。若要嵌入靜態網站，記得一併帶入對應的 highlight.js 或 Prism CSS。

深入原理擴充

HTML 實體轉義與程式碼區塊的交互

程式碼區塊是 Markdown 中的「免轉義」區域，但有幾個微妙的交互：

  1. 圍欄式區塊：三個反引號之間的所有內容都被視為純文字，<、>、& 不會被解析為 HTML。這就是為什麼你在區塊內寫 <div> 可以正常顯示。
  2. 縮排式區塊：行為相同，但因為沒指定語言，渲染器不知道要套什麼高亮——結果就是無色彩的純文字。
  3. 語言標記的降級：如果你寫 ```typescript 但渲染器不認識 typescript（有些只認 ts），會降級為無高亮。建議查閱目標渲染器支援的語言列表。
容易忽略的邊界案例：程式碼區塊的「結束圍欄」``` 必須在行首（前面只能有空格）。如果在結尾 ``` 後面不小心加了文字（例如 ``` some note），不會被識別為結束，會繼續往下找——可能導致整個文件後半段都變成程式碼的一部分。

診斷式疑難排解表

症狀可能原因解決方案
程式碼區塊沒語法高亮沒指定語言，或語言標記拼錯確認 ``` 後有正確語言名稱（如 python 而非 py）
行內 code 內的反引號外露只用一層反引號包住改用雙反引號 `` `code` `` 包住含反引號的內容
程式碼區塊提前結束程式碼內容有三個連續反引號改用更多反引號（四個）當圍欄，或用縮排式區塊
縮排式區塊前面被吃掉四格縮排式區塊會吃掉前四個空格改用圍欄式區塊（不影響內容縮排）
HTML 標籤在區塊外被渲染忘了包在程式碼區塊內用 ` 或 ``` 包住所有 HTML 程式碼

進階挑戰題

挑戰 1：寫一份「Docker 部署指南」，包含 Dockerfile（dockerfile 語言）、docker-compose.yml（yaml 語言）、bash 啟動腳本、以及一段 nginx.conf（nginx 語言）。要求：每段都有正確的語言標記，並且在行內 code 中提及容器名稱。
挑戰 2：在一個程式碼區塊中展示「如何用 Markdown 寫 Markdown」——用四個反引號包住三個反引號的範例，內部再包含行內 code 的雙反引號範例。三層巢狀都要正確渲染。
挑戰 3：用 pandoc 把一份含多種程式碼語言的 .md 轉成 HTML，然後手動加入 <link rel="stylesheet"> 引入 Prism.js 的 CSS，驗證語法高亮在瀏覽器中顯示正確。
